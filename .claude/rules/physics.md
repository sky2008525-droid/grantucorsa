# 物理モデルを書くときのルール

## 単位

**SI単位系が内部計算の標準。** m, kg, s, N, N·m, W, rad, rad/s。

- km/h、PS、kgf·m、mm、rpm は**入出力の境界でのみ**扱う。計算の中に持ち込まない
- **変数名に単位を入れる。** `speed_mps`, `torque_nm`, `wheelbase_m`, `omega_rads`
- 単位変換は1箇所に集約する。式の中に `/3.6` や `*9.80665` を散らさない

単位の取り違えは、物理的にあり得ない結果として現れず、**もっともらしい間違った結果**として現れる。これが最も危険。

## `vehicle.json` の扱い

- **数値をコードにハードコードしない。** 必ず `vehicle.json` から読む
- 値を読むときは `value` だけでなく `unit` を検証する。単位が想定と違えば例外を投げる
- `"unknown"` の項目を読んだら**例外を投げて止まる。** デフォルト値で代用しない
- `min` / `max` がある値は、探索するときその範囲を超えない

## テスト

**物理コードを変更したら、テストを追加または更新する。**（憲法ルール8）

- 変更前後で回帰テストを実行する
- **失敗した状態を「完成」と呼ばない**（ルール16）
- テストを skip して通さない。`pytest.mark.xfail` で誤魔化さない

コミット前フックが pytest を実行し、失敗すればコミットを止める。

## 検証

**実車データとシミュレーションを複数指標で比較する。**（ルール10）

0-100km/h だけが合っていても意味がない。同時に見る:

- 各ギアでの加速度の推移
- 変速タイミングと回転数
- 最高速（出典が取れたら）
- 制動距離
- 定常円旋回の横G

**1つの指標だけを合わせにいくと、他が破綻していることに気づけない。**

## 物理的にあり得ない値を採用しない

計算の途中と結果で、以下を検査して止まる:

- タイヤの摩擦限界を超える加速・減速
- エンジン出力から導かれる仕事率を超える加速
- 軸荷重の合計が車重と一致しない
- 荷重移動で軸荷重が負になる、または車重を超える
- スリップ率・スリップ角が定義域外

**「数値が常識的に見えるか」ではなく「保存則と拘束条件を破っていないか」で判定する。**

## エラーを隠さない

- `try/except: pass` を書かない
- 例外を握りつぶして 0 やデフォルト値を返さない
- NaN / inf が出たら、そこで止めて原因を報告する

## ZN6（FR）固有

- **駆動輪は後輪。** 加速時の荷重移動は駆動輪に**乗る**（FF とは逆）。
  定荷重モデルは FR では過小評価側に外れる
- 駆動系フローは `Engine → Clutch → Gearbox → Propeller Shaft → Final/Diff → Drive Shaft → 後輪`。
  **プロペラシャフトの回転慣性を落とさない**
- **後輪の複合スリップ（Combined Slip）がパワーオーバーステアの発生条件。**
  「後期に実装」ではなく AIドライバー（Phase 6）より前に必要
- GT はトルセンLSD標準。Open Diff は比較基準としてのみ残す
- **ファイナルは 4.100**（GT）。3.727 は G グレード用。取り違えると約10%の駆動力誤差
- **FA20 のトルクカーブは 4,000rpm 付近に谷がある。** 2点補間しない

## 現実の仕様と演出を分ける

**現実の車両仕様とゲーム上の演出を明確に分離する。**（ルール18）

アシスト、補正、見栄えのための誇張は物理モデルの中に混ぜない。
入れる場合は別レイヤーに置き、**オフにできる**ようにする。
検証は必ずアシストを全てオフにした状態で行う。
