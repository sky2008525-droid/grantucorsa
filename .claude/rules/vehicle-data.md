# 車両データ（vehicle.json）を編集するときのルール

**このファイルはプロジェクトで最も重要なデータ。** ここが壊れると全ての計算が壊れる。

## 必須フィールド

すべての数値項目は以下を持つ。

| フィールド | 必須 | 内容 |
|---|---|---|
| `value` | ○ | 値 |
| `unit` | **数値のみ○** | **SI単位**（`m`, `kg`, `N*m`, `W`, `s`）。無次元は `-`。形式名などの文字列には付けない |
| `source` | ○ | 下表の6種のいずれか |
| `confidence` | ○ | `source` の帯の**上限を超えない**こと（下回るのは可） |
| `min` / `max` | 推奨 | `official` 以外は原則付ける |
| `method` | `estimated` / `assumed` は必須 | 推定方法 |
| `note` | 任意 | 罠・制約・**棄却した候補とその理由** |

## source と confidence

| `source` | 定義 | confidence | 変更権限 |
|---|---|---|---|
| `official` | メーカー公式の技術資料（諸元表・サービスマニュアル） | 0.90 – 1.0 | **Level 0: 変更禁止** |
| `official_marketing` | 公式だが**販促資料**。測定条件が不明 | 0.70 – 0.89 | Level 1 |
| `measured` | 第三者による実測 | 0.70 – 0.89 | Level 1 |
| `secondary` | 二次情報（専門誌・レビュー）。**一次資料に当たれていない** | 0.70 – 0.89 | Level 1 |
| `estimated` | 物理モデル・幾何計算から推定 | 0.40 – 0.69 | Level 2 |
| `assumed` | AIによる仮定 | 0.0 – 0.39 | Level 3 |

`official_marketing` と `secondary` は CL1版の4分類には無かった。**追加した理由は `Docs/SPEC_ZN6.md` §5.2 を読むこと。**

### confidence は帯の上限だけを強制する

**帯を上に外れる = 過大申告 → エラー（コミットが止まる）**
**帯を下に外れる = 通常より慎重 → 警告のみ（`note` に理由を書く）**

防ぎたいのは過大申告であって、正直に低く申告することではない。
帯の下限まで強制すると、**嘘をつく方向に圧力がかかる。**

既にある実例:

- `tires.size` = `secondary` / **0.6** — 二次情報で、しかも諸元表PDFで裏が取れていない
- `brakes.rear_type` = `official` / **0.8** — 公式資料に載っているが、グレード間の対応が曖昧

どちらも帯を下回るが記述として正しい。**帯に合わせて上げると情報が失われる。**

### SI でない単位

`L`（排気量・タンク容量）と `persons`（乗車定員）のみ許容する。
**無条件に増やさない。** 追加するときは `Tools/validate_vehicle.py` の
`ACCEPTED_NON_SI_UNITS` に理由を書いて登録すること。

## 不明な値

**フィールド全体を文字列 `"unknown"` にする。**

```json
"effective_radius": "unknown"
```

- **推測で埋めない。** 空欄のまま残すのが正しい状態
- 「一般的に○○」「よく知られている」は出典ではない
- 出典が取れない値を `estimated` として入れるなら、`method` に**どう計算したか**を書く。
  書けないなら `assumed` にして confidence を 0.39 以下にする
- 採用を見送った候補は消さずに `note` に理由付きで残す
  （例: 有効半径 0.316m は算出根拠不明のため不採用）

## Level 0 を変更しない

以下はコミット前フックが変更を検出して**コミットを止める**。

- `engine.displacement`（排気量）
- `dimensions.wheelbase`（ホイールベース）
- `transmission.gear_ratios.*`（公式ギア比）
- `transmission.final_drive`（**`value` と `variants` の両方**）
- `mass.curb_mass`（公式車重）

**シミュレーション結果を実測値に近づけるために、ここを触ってはいけない。**
値が本当に間違っていると判断した場合は、一次資料を示したうえで人間の承認を得ること。

## ZN6 固有の罠

1. **ファイナルは単一値ではない。** `final_drive.variants` を消さない。
   G 6MT のみ 3.727、GT / GT"Limited" / 6AT 全車は 4.100。基準車両は **GT なので 4.100**

2. **全高 1,320mm はアンテナ込み。** ルーフ高は `roof_height` = 1.285m。
   二次情報に多い 1,300mm は**どちらとも一致しない**。3Dスケール補正には `roof_height` を使う

3. **`engine.torque_curve` は最重要未収集項目。**
   最大出力点と最大トルク点の2点だけで埋めない。FA20 は 4,000rpm 付近に谷がある

4. **重心高 0.46m は水平対向由来。** 直4の一般値（0.5m 台）に置き換えない

## スキーマ検証

編集したら必ず実行する。

```bash
python3 Tools/validate_vehicle.py Vehicles/ZN6/vehicle.json
```

コミット前フックも同じ検証を実行する。

## 基準車両を変えるとき

**`vehicle.json` を作り直すこと。** ギア比・ファイナル・車重・装備が連動して変わるため、
部分的な差し替えは必ず不整合を生む。`Docs/ZN6_BASELINE.md` も更新する。
