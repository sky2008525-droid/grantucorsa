## 大原則

### Tripo AI の生成モデルを CAD モデルとして扱わない（憲法ルール7）

生成物は**「公開画像から生成された視覚的近似モデル」**である。実測形状ではない。

### 物理計算と表示用3Dモデルを完全に分離する（ルール6）

- **3Dモデルの頂点座標を物理計算に流用しない**
- コリジョンメッシュを物理のジオメトリとして使わない
- 物理は `vehicle.json` の寸法から独立に構築する
- 寸法の**正解は常に `vehicle.json` 側**。3Dモデルをそれに合わせる（逆ではない）

## スケール補正の基準値（ZN6）

| 基準 | 値 | 用途 |
|---|---|---|
| **ホイールベース** | **2.570 m** | **第一基準。** 前後方向で最も誤差が出にくい |
| 全長 | 4.240 m | オーバーハングの検証 |
| 全幅 | 1.775 m | ミラー含まず |
| **ルーフ高** | **1.285 m** | **高さ方向の基準** |
| トレッド 前 / 後 | 1.520 / 1.540 m | **前後で異なる。同じ値を入れない** |

> ### 全高の公称値を使ってはいけない
> 公式諸元表の**全高 1,320mm はアンテナを含む**数値。ルーフ高は別に 1,285mm と明記されている。
> 二次情報に多い 1,300mm は**どちらとも一致しない**。
>
> 1,300mm を基準にすると **35mm の誤差が入ったまま「補正済み」と判定される。**
> ホイールベース基準と高さ基準の補正が食い違い、車体が縦に潰れる／伸びる。
>
> **`dimensions.roof_height` を使うこと。**

## 画像の一貫性（Phase 9）

- **前期のみ。** 後期はバンパー・ヘッドランプ・リアコンビが異なる
- **GT グレード（17インチ）。** RC は16インチ、G はホイールが異なる
- **BRZ を混ぜない。** 兄弟車でフロントバンパー・グリル形状が違う
- 86 は改造車の画像が非常に多い。**純正であることを必ず確認する**
- 画像には出典 URL と取得日を記録する（`Vehicles/ZN6/Images/SOURCES.md`）

## bpy の扱い

- **GUI 操作を前提にしない。** 全て `pip install bpy` でモジュールとして実行できる形で書く
- 手作業の手順を README に書くのではなく、スクリプトにする
- 実行結果は数値（誤差）で判定する。目視確認を前提にしない

## 演出と仕様を分ける（ルール18）

見栄えのための形状調整・マテリアル誇張は、**現実の車両仕様ではない**。
`vehicle.json` に混ぜない。3D側のパラメータは別ファイルに置く。
