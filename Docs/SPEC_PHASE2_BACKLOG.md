## 0. なぜ退避したか

Phase 1〜19 を順に踏むと、**車が動く前に大量の時間が消える。**

Phase 9〜15 は「実車画像の収集 → Tripo AI → Blender 補正 → PBR → UE5グラフィック → 音響 → 実在コース」という一連の作業で、**そのどれも第1完成目標（灰色の ZN6 が物理的に妥当な動きでテストコースを1周する）には不要**である。

**第1完成目標の確認に UE5 も 3Dモデルも要らない。matplotlib のアニメーションで足りる。**

3D と音響を先に作ると、次のことが起きる:

1. Tripo AI の生成品質のチューニングに時間が溶ける
2. Blender の環境構築と bpy スクリプトのデバッグに時間が溶ける
3. その間、物理モデルは1行も進まない
4. 「見た目はできたが、走らせると挙動がおかしい」状態で物理に戻ることになる

このプロジェクトの目的は「見た目がリアル」ではなく**物理的整合性**である。順序を逆にしてはいけない。

## 3. 3Dモデル構築パイプライン（Visual Layer）

> `SPEC_CL1_original.md` §7 に相当。対象車両を ZN6 に置き換えてある。

Tripo AI 生成モデルを「完全な実車モデル」とは扱わず、**「公開画像から生成された視覚的近似モデル」**と定義する。

**憲法**: Tripo AI の生成モデルを物理的に正確な CAD モデルとして扱わない（ルール7）。
物理計算と表示用3Dモデルを完全に分離する（ルール6）。**3Dモデルの寸法を物理計算に流用しない。**

### 3.1 画像収集と Tripo 入力（Phase 9〜10）

- **収集**: Front, Rear, Side, 3/4, Interior, Detail 等、**同一仕様（前期 / GT グレード / 純正）**の画像を集める
- **分類**: 画像の一貫性（改造の有無、グレード違い、前期/後期の別）を判定する
- **生成**: 選別された画像を Tripo AI へ入力し、GLB モデルを取得する

> **ZN6 固有の注意**
> - **前期と後期で外観が異なる**（バンパー、ヘッドランプ、リアコンビ）。基準車両は**前期**。後期の画像を混ぜない
> - **GT / GT"Limited" / G / RC でホイールとエアロが異なる**。基準は **GT（17インチ）**。RC は16インチ
> - 86 は BRZ と兄弟車で外観が似ている。**BRZ の画像を混ぜないこと**（フロントバンパー・グリル形状が違う）
> - 改造車の画像が非常に多い車種である。純正であることを必ず確認する

### 3.2 Reference Renderer による自動補正ループ（Phase 11）

Blender の GUI 操作を排除し、AI生成の Python (bpy) スクリプトで自動処理・検査する。

1. **全体スケール補正**: Tripo モデルのホイールベースと実車の公式値を比較し、スケールを正規化する
2. **レンダリング比較**: Blender 内で3Dモデルを実車画像と同じカメラ角度でレンダリングする
3. **画像比較**: 「実車画像 vs レンダリング画像」を比較し、シルエット、ホイール位置、ルーフライン等の誤差を計算する
4. **修正ループ**: 誤差に基づき Blender スクリプトを更新し、局所補正（Overhang, Track, 頂点修正）を実行する。誤差が閾値以下になるまで繰り返す
5. **個別生成**: ホイール、タイヤ、ブレーキ等、Tripo の精度が低い部品は、公開寸法に基づき Blender で幾何学的に自動生成して置換する

#### スケール補正に使う基準値（ZN6）

| 基準 | 値 | source | 備考 |
|---|---|---|---|
| **ホイールベース** | **2.570 m** | official | **スケール正規化の第一基準。** 前後方向で最も誤差が出にくい |
| 全長 | 4.240 m | official | オーバーハングの検証に使う |
| 全幅 | 1.775 m | official | ミラー含まず |
| **ルーフ高** | **1.285 m** | official | **高さ方向の基準はこれを使う（下記の警告を読むこと）** |
| トレッド（前 / 後） | 1.520 / 1.540 m | official | 前後で異なる。**同じ値を入れない** |

> ### 警告: 全高の公称値を使ってはいけない
>
> 公式諸元表は **全高 1,320mm** と記載しているが、これは**アンテナを含む**数値である。
> **ルーフ高は 1,285mm** と別に明記されている。
>
> 一方、二次情報の多くは **1,300mm** と記載する。**この値はどちらとも一致しない。**
>
> 1,300mm を基準にスケール補正すると、**35mm の誤差が入ったまま「補正済み」と判定される。**
> ホイールベース基準の補正と高さ基準の補正が食い違い、車体が縦に潰れる／伸びる。
>
> **`dimensions.roof_height` = 1.285m を使うこと。**
>
> 出典: `Docs/ZN6_BASELINE.md` 罠②

### 3.3 メッシュクリーンアップと PBR（Phase 12）

- **トポロジ修正**: Non-manifold、重複頂点、不正な法線を自動修正し、Body / Glass / Wheel 等にパーツ分離する
- **UV展開**: 自動 UV 展開を実行し、結果を検査する
- **マテリアル (PBR)**: 実車写真の影（Shadow / Reflection）を焼き付けず、**Intrinsic Albedo** を推定させる。自動車塗装（Clear Coat）、ガラス（Transmission）、タイヤ（Roughness）等を適切に設定する
- **LOD・コリジョン**: 描画用 LOD と、物理とは独立した簡易コリジョンを生成する

**コリジョンメッシュを物理計算のジオメトリとして使わないこと。** 物理は `vehicle.json` の寸法から独立に構築する。

Nanite / Lumen 対応。

**分離構造を崩さないこと**: 生成メッシュは描画専用（Visual only）。物理計算は独立した Physics Model が担当する。

| Rendering | 60–120 Hz |
| Physics | 高頻度サブステップ |

## 5. 音響モデル（Phase 14）

公開無料素材を使用する。実車録音は行わない（§1.2 前提条件）。

| 連動 | 内容 |
|---|---|
| RPM | Pitch / Volume |
| スロットル | Load（負荷による音色変化） |
| タイヤ状態 | Slip（スキール音） |
| 路面状態 | クロスフェード |

> **FA20 固有の注意**
> FA20 は水平対向4気筒で、直4とも V6 とも異なる排気音を持つ。
> **等長エキマニ／不等長エキマニで音が変わる**ため、素材選定時に前提を記録すること。
> ここで選んだ素材は**演出**であって実測ではない。
> 憲法「現実の車両仕様とゲーム上の演出を明確に分離する」（ルール18）に従い、
> 音響パラメータを `vehicle.json` に混ぜないこと。**別ファイルに置く。**

## 8. ライセンスとリポジトリ運用

Phase 9 以降で**収集した実車画像と Tripo AI 生成モデルをリポジトリに置く設計**になっている。

- **ライセンス上の問題が出るのはそのとき。** それまでにリポジトリを private にしておくこと（`Docs/HANDOFF.md` §8）
- 画像には出典 URL と取得日を記録する。`Vehicles/ZN6/Images/SOURCES.md` を作る
- Tripo AI の生成物の利用規約を、Phase 10 の着手時点で確認する
- **リポジトリが急激に肥大する。** このタイミングで Git LFS の導入を判断する（`.gitignore` に保留として記載済み）

### このフェーズで追加するディレクトリ

```
Vehicles/ZN6/
├── Images/     # 収集した公開画像（+ SOURCES.md）
├── Tripo/      # Tripo入力用画像、出力GLB
├── Raw/        # Blender処理前メッシュ
├── Clean/      # Blender処理後メッシュ
├── PBR/        # 生成テクスチャ
└── Export/     # UE5向けFBX/UASSET
Blender/        # bpyスクリプト
Audio/          # 音声素材、加工スクリプト
Unreal/         # UE5プロジェクト（Phase 8 で先に作る）
```

**先に空ディレクトリを作らない。** 中身が発生したときに作る。
