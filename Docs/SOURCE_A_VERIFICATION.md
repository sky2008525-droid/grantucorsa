## ⚠ このPDFはテキスト抽出できない

**先に読むこと。これを知らずに再照合すると同じ誤りを再生産する。**

このPDFはフォントに ToUnicode CMap を持たない。テキスト抽出すると:

- **数値がすべて消える**（空白として落ちる）
- 日本語がすべて文字化けする（`型式` → `ࣜܕ`）
- ラテン文字は **コードポイントが31ずれる**（`FA20` → `'"`、`kg` → `LH`、`mm` → `NN`）

つまり **抽出テキストからは値もグレード列の対応も読み取れない。**

### 正しい読み方

PDFを**画像に描画してから読む**。ページレンダラを pip で入れられる（システム依存なし）:

```bash
python3 -m pip install pypdfium2 pillow
python3 -c "
import pypdfium2 as pdfium
pdf = pdfium.PdfDocument('Vehicles/ZN6/References/86_spec_201502.pdf')
pdf[0].render(scale=5).to_pil().save('spec.png')
"
```

諸元表は1ページに6グレード列が並ぶ密な表なので、`scale=5` 程度が要る。
上下に分割しないと細部が潰れる。

**この罠が、下記の誤りの原因だった。**

## 見つかった誤り（修正済み）

### `brakes.rear_type` が G グレードの値だった

| | |
|---|---|
| **修正前** | `"ディスク"` / `official` / confidence 0.8 |
| **修正後** | `"ベンチレーテッドディスク"` / `official` / confidence 1.0 |

諸元表の「ブレーキ リヤ」欄は、**GT"Limited" と GT が「ベンチレーテッドディスク」、G が「ディスク」**。
基準車両は **GT** なので、正しくは ベンチレーテッドディスク。

修正前の note には「公式諸元表の抽出テキストではグレード間の対応が曖昧」とあった。
**抽出テキストではグレード列の対応が取れないため、隣の G 列の値を拾っていた。**
描画して読めば列の対応は一意に決まる。

#### これが物理に効く範囲

リヤがベンチレーテッドかソリッドかは、**ブレーキ容量と熱容量**の推定に効く。
Phase 4 で制動モデルを書くとき、ディスク径・厚みの推定初期値が変わる。
100-0km/h の制動距離の検証（`validation_targets.braking_100_0_m`）にも影響する。

### 注記が要るもの（1件・値は変更しない）

**`steering.type`** = `"ラック＆ピニオン式 電動パワーステアリング"`

諸元表の「ステアリング」欄は **「ラック＆ピニオン式」のみ**。
「電動パワーステアリング」は別の欄（**主要燃費改善対策**: 筒内直接噴射、可変バルブタイミング、電動パワーステアリング）に書かれている。

**値としては正しいが、2つの欄を合成している。** どちらも同じPDF内の official 記述なので
source は `official` のままでよい。再照合時に「ステアリング欄にそんな記述はない」と
誤って修正されないよう、ここに記録しておく。

## 罠2件を一次資料で裏取りできた

`Docs/ZN6_BASELINE.md` が二次情報レベルで警告していた2件が、**公式諸元表の本文で確認できた。**

### 罠① ファイナルは単一値ではない

減速比の行:

| グレード | 6速SPDS(AT) | 6速マニュアル |
|---|---|---|
| GT"Limited" | 4.100 | 4.100 |
| GT | 4.100 | 4.100 |
| G | 4.100 | **3.727** ＊1 |

**脚注＊1**: 「トルセン®LSD を選択した場合、減速比は 4.100となり、燃料消費率は12.4km/L になります。」

`vehicle.json` の `final_drive.variants` の4パターンと**完全に一致**。推測ではなく公式脚注が根拠。

### 罠② 全高はアンテナ込み

全高の行にそのまま書かれている:

> **1,320（アンテナを含む数値。ルーフ高は 1,285）**

括弧内が公式表記そのもの。**二次情報に多い 1,300mm はこのPDFのどこにも出てこない。**
3Dモデルのスケール補正には `roof_height` = 1.285 m を使うこと。

## 諸元表に「載っていない」ことを確認した項目

`unknown` のままにしておく根拠。**探しても無かった**のであって、見落としではない。

- **純正タイヤサイズ / ホイールサイズ** — 諸元表にタイヤの行が存在しない（`tires.size` が `secondary` である理由）
- **Cd値 / 前面投影面積** — 記載なし
- **前後重量配分 / 前軸重・後軸重** — 記載なし
- **スプリングレート / ダンパー減衰力 / スタビ径 / ジオメトリ** — 形式名のみで数値なし
- **ブレーキディスク径・厚み / マスターシリンダー径 / 前後配分** — 形式名のみ
- **トルクカーブ** — 最高出力点と最大トルク点の2点のみ（**これだけで補間してはいけない**）
- **レブリミット / アイドル回転数 / エンジンフリクション / 慣性モーメント** — 記載なし
- **0-100km/h / 最高速 / 制動距離 / 横G** — 記載なし（性能値は諸元表の範囲外）

これらは Source B 以降を当たるしかない。

## この諸元表の適用範囲

- **RC グレードは載っていない。** 2015年2月時点で既に廃止されているため（`ZN6_BASELINE.md` の記述と整合）
- 掲載グレードは **GT"Limited" / GT / G** の3種 × 6速SPDS(AT) / 6速マニュアル = 6列
- **後期型（2016年8月〜）は対象外。** 後期は最高出力・最大トルクが変わる（152kW / 212N·m）

## 再照合するときは

1. **必ず描画して読むこと。** テキスト抽出は値もグレード列も取れない（冒頭参照）
2. GT / 6速マニュアル の列を見ること。**隣の列と1つずれると別グレードの値になる**
3. 差異を見つけたら、まず `Docs/ZN6_BASELINE.md` の罠2件に該当しないか確認する
4. Level 0 パラメータ（排気量・ホイールベース・公式ギア比・公式車重・ファイナル）に
   差異があった場合は、**勝手に直さず人間の承認を得ること**。コミット前フックが止める
