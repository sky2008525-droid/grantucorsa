### 0.4 物理にも、塞いでいない穴がある

**「文書化したから良い」ではない。穴は穴のまま残っている。**

1. **接地モデルが半分しか繋がっていない**（最大の問題）
   `Physics/ride.py` / `ZN6Ride.cpp` は上下・ピッチ・ロールを力の釣り合いで
   解いているが、**そこで出た接地力をタイヤモデルに渡していない。**
   タイヤの垂直荷重は今も準静的モデル（`wheel_loads_n`）が出している。
   つまり「車輪が浮く」のは見た目と接地判定だけで、**浮いた車輪の
   グリップは消えていない。** 段差で跳ねてもタイヤは効き続ける。
   これは「重力の物理演算ができていない」という指摘への回答として不完全。

2. **スタビライザーが入っていない**
   `arb_front` 18mm / `arb_rear` 14mm は実測で分かっているのに、
   アーム長とレバー比（`suspension.geometry`）が `unknown` なので
   ロール剛性に直せない。結果、ばねだけで出した前ロール剛性配分は
   **0.441**、`vehicle.json` の仮定値は **0.600**。
   **2つのモデルが別の車を表している状態が放置されている。**

3. **前軸荷重比が2通りある**（[issue #29](https://github.com/sky2008525-droid/grantucorsa/issues/29)）
   重心位置経由 0.530 と `weight_distribution_front_pct` 0.542 が
   1.2 点（重心 31mm 相当）食い違う。どちらも `estimated`。未解決。

4. **積分がまだ1次**（[issue #28](https://github.com/sky2008525-droid/grantucorsa/issues/28)）
   発進 2 秒後の速度が刻みで 2.49 / 3.32 / 3.91 / 4.25 / 4.43 m/s と動く。
   車輪のサブステップが要る。未着手。

### 1.2 重要な作業上の制約（次セッションが最初にぶつかる）

1. **UE エディタが起動しているとビルドできない。**
   Live Coding がビルドを掴む。`taskkill //F //IM UnrealEditor.exe` で落とす。
   `awk '{print $2}'` で PID を取るのは日本語ロケールで失敗する。
   **`//IM` でイメージ名指定すること。**

2. **Git Bash のパス変換で `/Game/...` が壊れる。**
   `C:/Program Files/Git/Game/...` に書き換えられ、**エラーで止まらずに
   別のマップが開く**。`MSYS2_ARG_CONV_EXCL="/Game"` を使う。
   `"*"` にすると今度は `.uproject` のパスが壊れて UE が 1 秒で死ぬ。
   `Tools/launch_game.sh` に対処済み。

3. **サブエージェントは4本同時に立てると全部落ちた**（セッション制限）。
   このセッションで実際に起きた。**1〜2本ずつにすること。**

4. **UE のビルドは並列に走らせられない。** メモリ制約で並列度2まで落ちる。
   サブエージェントには「ビルドを走らせるな」と明示すること。

### 1.3 ボディカラーの調査結果（次セッションが使える事実）

車体メッシュ `/Game/ZN6/Vehicle/body/ZN6_body/StaticMeshes/ZN6_body` は
**マテリアルスロットを 37 個持つ**。全て `MaterialInstanceConstant` で、
親は `MI_Default_Blend`（Interchange の glTF 既定）。

**親に `BaseColorFactor` というベクタパラメータがある。**
つまり実行時に `UMaterialInstanceDynamic` を作って
`SetVectorParameterValue("BaseColorFactor", Colour)` すれば色を変えられる。

**ただし 37 スロットのうちどれが「塗装」かは未特定。**
スロット名の例: `reflector` / `tail_light` / `black` / `chrome` / `body` /
`Color_A02` / `Color_B01` …。ガラス・灯火・クロームまで塗ると車が単色の
塊になる。**塗る対象を名前か既定色で選別する必要がある。**

> 次セッションはここから始められる。調査をやり直さないこと。

### 2.2 優先順位（依頼者の指摘の重さ順）

**A. 接地力をタイヤへ繋ぐ（物理の穴。最優先）**

`Physics/vehicle.py` の `step()` が `wheel_loads_n()` で出している垂直荷重を、
`Physics/ride.py` の接地力で置き換えられるようにする。

- **既定では今までどおり**（準静的）。参照値がビット単位で変わらないこと
- 有効にしたとき、**浮いた車輪のグリップが 0 になる**こと
- 前後の荷重移動は定常状態で今と一致するはず（既に検査がある）
- 左右は一致しない。**合わせにいかない**（憲法ルール3）。
  差が出ることを検査で数値として報告する
- C++ へ移植し、`AZN6VehicleActor` で切り替えられるようにする

**B. 見た目（依頼者が「完成度が低い」と言っている中身）**

1. **タイヤ痕**（デカール）。スリップ率が閾値を超えたら路面に残す
2. **タイヤの煙**（Niagara）。スリップ率と荷重で量を決める
3. **マフラーの煙**。スロットルと回転数で
4. **路面の作り込み**。ひび割れ・継ぎ目・縁石。
   **周囲の地面より厚みを持たせて立体にする**（今は同じ平面に置いた帯）
5. **ボディカラー選択**（§1.3 の調査結果を使う）

> **視覚層の評価オラクルは見る人の主観**（`AGENT_TOPOLOGY.md` §4）。
> ここは「良く見えるまで回してよい」層である。**必ず自分で見て判断する。**

**C. コースを増やす**

- **実在コースのレイアウトを再現しない。** 理由は
  `Docs/PHASE15_DATA_LICENCE.md`。首都高・つくばの形をトレースするのは
  ライセンス上の問題になる。**架空のコースを作り、実在コース名を名乗らない**
- 性格の違うものを3本以上（低速テクニカル／高速／勾配のある峠）
- 形式は `Tracks/physics_test_track.json` に合わせる
  （`Blender/build_track.py` と `Tracks/real_course.py` が読む）
- 曲率を連続させる。**直線とコーナーを角で繋ぐと車が跳ねる**

**D. 雨**

- タイヤの μ が濡れでどう変わるかの**出典が無い。** `assumed` として明示し、
  それを使った結果は検証に使えないことを画面にも出す
- 乾燥時に既存の結果がビット単位で変わらないこと
- 視覚（雨粒・路面の反射・水しぶき）と物理を分けて実装する

**E. 入力機器（PS5 / T300RS / シフター）**

- **実機が無いので検証できない。** どこまでが確認済みでどこからが未検証かを
  必ず区別して書くこと（憲法ルール6）
- `FZN6DriverFeel` の平滑化は**キーボード用**。アナログ入力では入力が鈍る。
  デバイスによって切り替える必要がある
- H パターンのシフターは**絶対位置**。今の実装は相対変速
  （`ZN6_ShiftUp` / `ZN6_ShiftDown`）なので噛み合わない

**F. GT7 相当機能の洗い出し**

`Docs/SPEC_GT7_GAP.md` を作る。**出典 URL と確認日を必ず書く。**
「入れるべきでないもの」は理由つきで書く
