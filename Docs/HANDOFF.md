## 1. 対象車両の変更（最重要）

**CL1（Honda Accord Euro R）→ ZN6（トヨタ86）**

元仕様書は全編 CL1 前提で書かれている。単語置換では済まない。駆動方式が変わるため、以下は設計判断そのものを見直す必要がある。

| 項目 | CL1 | ZN6 |
|---|---|---|
| 駆動方式 | FF | FR |
| エンジン | H22A（直4） | FA20（水平対向4気筒） |
| デフ | — | トルセンLSD（標準装備） |

**要書き換え箇所（既知）**

- **§6.2 デファレンシャル** — 「FF車であるCL1において重要」という記述がある。FR + トルセンLSD 前提に全面書き換え。
- **§6.5 荷重移動** — 加速時の荷重移動が駆動輪に与える影響が FF と FR で逆になる。トラクション限界の扱いを見直す。
- **§8.3 AIドライバー** — PID の制御方針が FF 前提（アンダー主体）になっていないか確認。FR はパワーオーバーステアを起こす。
- **§8.4 Vehicle Validity** — 「FFの特性など」という例示を FR の特性に差し替え。
- **§4 ディレクトリ構造** — `Vehicles/CL1/` → `Vehicles/ZN6/`
- **§10.1 レポート見出し** — `CL1 DIGITAL TWIN UNCERTAINTY REPORT` → `ZN6 ...`

**FA20 固有で追加検討が要る点**

- 水平対向エンジンは重心が低い。CG高さの推定初期値を直4前提で置いてはいけない。
- 4400rpm 付近のトルクの谷が知られている。トルクカーブを2点（最大出力/最大トルク）だけで補間すると、この特性が消える。トルクカーブは複数データポイントを必須とする。

## 3. 憲法（ルール）の構造変更

元仕様書 §5.1 は18のルールを `AGENTS.md` 1枚に並べる想定だった。これを性質別に3層へ分割する。

理由: CLAUDE.md はコンテキストであって強制設定ではない。確実にブロックしたい項目はフックで実装しないと守られない。また1ファイルが長いほど遵守率が下がる（目安200行以下）。

### 層1: フックで強制（`.claude/hooks/`）

機械的に検証できるもの。Claude の判断に関係なく実行される。

- Level 0 パラメータ（排気量・ホイールベース・公式ギア比・公式車重）の変更をコミット前に検出して停止
- `vehicle.json` の JSON スキーマ検証（`source` / `confidence` / `unit` の必須チェック、SI単位、`unknown` の許容）
- pytest 失敗時のコミット停止

### 層2: CLAUDE.md（150行以内・全セッション読み込み）

判断を要するもの。

- 実車データを捏造しない
- 出典のない数値を実測値として扱わない
- ラップタイムだけを合わせる最適化の禁止
- 物理計算と表示用3Dモデルの完全分離
- エラーを隠蔽しない
- 既存コードを読まずに変更しない

### 層3: `.claude/rules/`（`paths` フロントマターでスコープ）

該当ファイルを触るときだけ読み込まれる。

- `physics.md` → `paths: ["Physics/**/*.py"]`
- `vehicle-data.md` → `paths: ["Vehicles/**/*.json"]`
- `blender.md` → `paths: ["Blender/**/*.py"]`（Phase 11 まで未使用）

**注意**: 仕様書全文を CLAUDE.md に入れないこと。`Docs/SPEC_ZN6.md` は自動ロードせず、必要なときだけ読む。

### ファイル名について

Claude Code が読むのは `CLAUDE.md` であり `AGENTS.md` ではない。他のエージェントも併用する予定がなければ `CLAUDE.md` 一本でよい。併用する場合は `AGENTS.md` を本体にして、`CLAUDE.md` の先頭に `@AGENTS.md` と書いてインポートする。

## 5. Day 1 の作業手順

データ収集を先に全部やらないこと。14カテゴリのリストを埋める作業になり、何のために集めているかが分からなくなる。代わりに、初日にエンドツーエンドの検証ループを1本通す。

1. リポジトリと Claude Code の起動
2. ~~確実な公式値だけを10個程度集める~~ → **完了済み**
   `Vehicles/ZN6/vehicle.json` に公式値38項目を収録済み。
   縦断モデルに必要な値（車重・ギア比・ファイナル・出力・トルク）は全て揃っている。
   未取得はタイヤ有効半径のみ。純正サイズ確定後に幾何計算すること。
3. **最小の縦断モデルを Python で書く**（200行程度）
   タイヤは定数μ、サスペンションなし、空力は Cd のみ
4. **0-100 km/h を計算し、公開されている実測値と比較する**

### ここで必ず起きること

ZN6 の 0-100km/h の実測値は情報源によってばらつく（メディア・グレード・仕様地・測定条件による）。**初日から「実測値そのものが不確実」という問題に直面する。**

これは仕様書の confidence システムが本当に機能するかを確かめる最良のテストケース。ここで「どの実測値を基準とするか」のルールを決められないなら、後段の Reality Validator も機能しない。

**このループが通れば、あとは全部その精緻化。** タイヤモデルを Fiala に、1自由度を6自由度に、と段階的に置き換えていける。

### vehicle.json について

最初から14カテゴリ分のスキーマを設計しない。**物理モデルが実際に読む項目から育てる。** 初期は20フィールド程度で足りる。

Claude Code とチャット（claude.ai プロジェクト）は**コンテキストを一切共有しない**。橋渡しはファイルシステムと Git のみ。

| 役割 | 場所 |

## 8. リポジトリの初期状態について

リポジトリ: `https://github.com/sky2008525-droid/grantucorsa`

作成直後の状態に3点、着手前に対処すべきものがある。

### `.gitignore` が別言語のテンプレート

初期状態で入っているのは **AL（Microsoft Dynamics 365 Business Central）用**のテンプレート。Python にも UE5 にも合わない。加えて `.vscode/` を無視する設定が入っているため、VS Code の設定を共有できない。

Python + venv + UE5 + Blender + OS生成ファイル向けに全面差し替えが必要。`.vscode/` は無視せず共有する方針とする。

### public で作成されている

このプロジェクトは公開情報のみを扱う建て付けなので機密性の問題は薄いが、Phase 9 以降で **収集した実車画像や Tripo AI 生成モデルをリポジトリに置く設計**になっている。ライセンス上の問題が出るのはそのとき。

private にしておき、公開したくなったら切り替える方が安全。逆方向（public で公開済みのものを private に戻す）は、既にクローンされていた場合に取り返しがつかない。

### `main` への直コミット運用

憲法に「AIによるパラメータ変更は Git で記録し、変更理由を明記する」とある。Phase 4（物理モデル実装）に入る前にブランチ運用へ切り替えること。それまでは直コミットで構わない。
