## 選定理由

### なぜ前期か

**Source A の完全な一次資料が手元にある。** トヨタ公式の主要諸元表（2015年2月版）を取得済みで、寸法・重量・エンジン・全ギア比・減速比・サスペンション形式・ブレーキ形式が1枚で揃っている。後期型で同等の資料を確保できるまで、前期を基準にする方が憲法（§6.1 情報収集の優先順位）に忠実。

副次的な理由として、2012〜2016年は各誌のインプレッションと実測が最も多く出た時期で、Source B の検証データが集めやすい。

出典: `https://toyota.jp/pages/contents/86/001_p_004/pdf/spec/86_spec_201502.pdf`
**このPDFは `Vehicles/ZN6/References/` に保存すること。** URLは将来失効する。

### なぜ GT か

G は 6MT のファイナルが 3.727 でオープンデフ。RC は 2015年2月に廃止済みで、リアがソリッドディスク・16インチと装備が異なり、二次情報も少ない。

GT はトルセンLSDと4.100ファイナルを持ち、元仕様書 §6.2 が要求する LSD モデリング（Preload / Accel Lock / Decel Lock）の対象になる。GT"Limited" とは内装差のみで、6MT の車重はどちらも1,230kgで同一。走行性能上の差がないため、装備の少ない GT を採る。

### なぜ 6MT か

6AT を選ぶとトルクコンバータの特性とシフトロジックのモデリングが加わる。これは元仕様書のスコープ外の作業量で、第1完成目標には不要。元仕様書の記述も MT 前提が多い。

### なぜ日本仕様か

公式諸元表が日本仕様で、出力表記が JIS ネット値。北米仕様は SAE 表記で数値が変わり、装備重量も異なる。混在させると §5.1 の「公式値と推定値を混在させない」が守れない。

## 検証で判明した重要事項2件

### 1. ファイナルギア比は単一値ではない

公式諸元表の脚注に、G 6MT の減速比が **3.727**、トルセンLSDを選択した場合に **4.100** になると明記されている。GT / GT"Limited" および 6AT 全車は 4.100。

**「ZN6のファイナルは4.100」と一括りにすると、Gグレードのデータを引いたときに約10%の駆動力誤差が入る。** 0-100km/h の検証で原因不明のズレとして現れ、Optimizer がタイヤμを不当に触って辻褄を合わせる典型的な事故につながる。

`vehicle.json` の `transmission.final_drive.variants` に全パターンを記録済み。

### 2. 全高の公称値が二次情報と一致しない

公式諸元表は **全高 1,320mm（アンテナを含む数値。ルーフ高は 1,285）** と明記している。一方、二次情報の多くは 1,300mm と記載する。1,300mm はどちらとも一致しない。

3Dモデルのスケール補正（元仕様書 §7.2）で 1,300mm を基準にすると、35mm の誤差が入ったまま「補正済み」と判定される。**`roof_height` = 1.285m を使うこと。**

## 重心高について（CL1版からの改善点）

元仕様書 §5.2 の JSON 例は、CL1 の `cg_height` を `estimated` / confidence 0.35 としていた。

ZN6 ではトヨタが「超低重心（重心高460mm）」として公表しており、Level 2（探索可能）パラメータの探索範囲を大幅に狭められる。ただし出典が販促資料であり測定条件（乗員・燃料の有無）が不明なため、`official_marketing` / confidence 0.75 として記録し、min/max を 0.44〜0.48 に設定した。

これは水平対向エンジン由来の特性で、直4の CL1 と同じ初期値を置いてはいけない。

## トルクカーブに関する警告

`vehicle.json` の `engine.torque_curve` は現時点で `unknown`。**最重要未収集項目。**

FA20 は 4,000rpm 付近にトルクの谷があることが広く知られている。最大出力点（7,000rpm）と最大トルク点（6,400〜6,600rpm）の2点だけでスプライン補間すると、この特性が完全に消える。加速シミュレーションでは中回転域が実車より速くなり、その誤差を Optimizer が別のパラメータで吸収してしまう。

シャシダイ実測（ホイール出力ではなくエンジン軸換算）を Source B で複数取得し、ばらつきを範囲として保持すること。

## Day 1 で決着させること

`vehicle.json` の `validation_targets` は全て `unknown` にしてある。

0-100km/h の実測値は、媒体・グレード・仕様地・測定条件によって値がばらつく。**「どの出典を基準とするか」のルールを先に決めること。** 決められないなら、Reality Validator（元仕様書 §8.4）は後段で必ず破綻する。

推奨する決め方: 単一の値を採らず、**複数出典の範囲**として保持し、シミュレーション結果がその範囲に収まるかで判定する。元仕様書 §5.2 が数値に min/max を持たせている思想と一貫する。
